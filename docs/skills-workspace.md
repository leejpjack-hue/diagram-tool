# DiagramTool skills workspace

The production Worker (`worker/index.ts`) routes the skills API to the `DiagramSkillsAgent` Durable Object. It is a Think agent backed by a Computer Workspace and exposes skill sources in strict priority order from `getSkills()` (`worker/skills-agent.ts` and `worker/skill-sources.ts`):

1. **Primary (`workspace:/workspace/.agents/skills`)** — the Durable Object Workspace at `/workspace/.agents/skills/`, stored in the Durable Object's SQLite.
2. **Secondary (`r2:agents:skills` and `bundle:agents:skills`)** — an optional R2 bucket bound as `SKILLS_BUCKET` under key prefix `agents:skills/`, followed by the verified checked-in skill bundle (`skills/skills-bundle.json` / `SECONDARY_SKILL_BUNDLE`), both resolving skill locations under `agents:skills/<name>`.

By default, the checked-in `skills/type-to-flow/` files are copied into an empty Workspace once on first start (`STARTER_SKILLS` generated by `npm run generate:skills`). The Workspace is authoritative afterward: cold wakes, Worker redeploys, and secondary sources never overwrite operator edits or recreate deleted Workspace files. When a staging or non-Workspace-seeded deployment sets `SKILLS_SKIP_WORKSPACE_SEED=1` (or when a skill is not present in `/workspace/.agents/skills/`), the catalog and activation paths load the skill from the verified secondary `agents:skills` path.

## Secondary publish path (`agents:skills`), package metadata, and precedence

`npm run generate:skills` (`scripts/generate-skill-seed.mjs`) packages each checked-in skill under `skills/<name>/` into `skills/skills-bundle.json` and `worker/generated-skill-seed.ts`. Every secondary skill package carries:

- `version` — must be non-empty and match `metadata.version` in `<name>/SKILL.md` frontmatter (for `type-to-flow`, `"1.0.0"`).
- `checksum` — canonical `sha256:<64-hex>` digest computed over all sorted relative files in the skill package (`<relativePath>\0<content>\0`).

Before a secondary package from `r2:agents:skills` or `bundle:agents:skills` is merged into the catalog, `verifySkillPackage()` (`worker/skill-sources.ts`) verifies its `SKILL.md` frontmatter, `version`, and `sha256` `checksum`. Verification is fail-closed: a package with missing or mismatched version/checksum metadata is recorded as `InvalidSkill` and never enters the catalog.

Precedence is explicit and fail-closed:

- When both Workspace and a secondary source provide the same skill name, the primary Workspace skill (`/workspace/.agents/skills/<name>`) wins and the secondary duplicate is ignored.
- Secondary sources are read-only and never write into `/workspace/.agents/skills/` or overwrite operator Workspace edits.
- If an operator has a broken `SKILL.md` under `/workspace/.agents/skills/<name>/SKILL.md`, the secondary source does not silently mask that broken Workspace file.

### Binding an R2 bucket under prefix `agents:skills` later

`wrangler.jsonc` does not bind a production R2 bucket by default so free-plan deploys incur no R2 spend. To serve secondary packages from R2 in an environment that provisions a bucket later:

1. Upload each skill folder under the `agents:skills/` key prefix (`agents:skills/<name>/SKILL.md`, `agents:skills/<name>/references/...`, `agents:skills/<name>/scripts/...`) along with `agents:skills/skills-bundle.json` (or `metadata.version` and `metadata.checksum` in `SKILL.md`).
2. Add the `SKILLS_BUCKET` R2 binding to `wrangler.jsonc`:

   ```jsonc
   "r2_buckets": [
     { "binding": "SKILLS_BUCKET", "bucket_name": "<your-skills-bucket>" }
   ]
   ```

`DiagramSkillsAgent.getSkills()` automatically places `r2:agents:skills` after `workspace:/workspace/.agents/skills` and ahead of `bundle:agents:skills`.

The skill and its deterministic converter descend from the `02-cf-skills` spike (`PROOF.md`, `type-to-flow-skill/`, and `sample/input.json`); the spike Worker was not promoted. DT pins Agents 0.32.0, Think 0.23.0 and Computer 0.8.0 because these APIs are experimental. See Cloudflare's [skills-as-files release](https://developers.cloudflare.com/changelog/post/2026-10-29-agent-skills-from-files/) for the Workspace and next-turn discovery contract.

`GET /api/skills` lists the Workspace catalog; `POST /api/skills/<name>/activate` loads the skill body and resource list through the SDK's catalog activation. `POST /api/skills/type-to-flow/run` activates that skill and runs the statically imported `skills/type-to-flow/scripts/type-to-flow.js` converter (free-plan deploy; no Dynamic Workers / `worker_loaders`). It takes `{ "text": "one step per line", "title": "optional" }`; it returns `{ flow, mermaid, warnings, ambiguities }`. No model or API key is needed for this converter. Decision branches are inferred. `ambiguities` names each inferred decision in one sentence. When that list is non-empty, the editor shows it and does not write those decision edges until the operator confirms or edits the no branch. Cancel leaves the current board as it was. A result with no ambiguity list still maps after it validates. In a Flow board, the **Skills** catalog lists each skill's name and description from `SKILL.md` frontmatter. **Activate** calls the host activate path. For `type-to-flow`, the editor then runs the converter and maps the graph only after that result validates; a failed activate or map shows an error and leaves the current board as it was. **Run type-to-flow** inside **Type steps** still sends the steps to the same run path. Do not include secrets. Completed execution records are discarded after the result is read; interrupted runs follow the SDK's retention behavior. The existing **Build board** button remains local. The graph is saved as the board's ordinary native DSL, and the returned Mermaid is shown in the Type steps panel for the result.

## Catalog in /app

The editor requests `GET /api/skills` when a board opens and again when the operator chooses **Reload skills**. Reload uses `cache: no-store` and `GET /api/skills?reload=1`. The query is only a browser cache-buster: the Worker routes on the pathname and calls `loadSkillCatalog` on `getSkills()` every time, so the Workspace stays authoritative. A skill folder added under `/workspace/.agents/skills/` appears after Reload without a Worker redeploy and without reattaching the Durable Object. The in-app list is not kept across Reload.

That refresh does not change the type-to-flow runner. Activation can see an edited `SKILL.md` immediately. Running or mapping type-to-flow still executes the converter statically imported in the Worker build. Editing `scripts/type-to-flow.js` in the Workspace does not change the runner until a Worker redeploy (free-plan static import, #127). The catalog states this in the editor.

## Add or edit a skill without a Worker redeploy

An operator must first provision `SKILLS_ADMIN_TOKEN` as a Worker secret using the platform's secret store. Do not put the token or other secrets in skills, repository files, or shell history. Without this secret, file writes are disabled. The public routes do not expose Think's general chat or Workspace filesystem.

1. Create a folder whose name follows the Agent Skills naming rules, with a `SKILL.md` starting with `name` matching the folder and a nonempty `description`. Keep supporting files under `scripts/`, `references/`, or `assets/`.
2. For each UTF-8 file, write it into the durable Workspace over the authenticated administration endpoint. For example, with `DT_URL` set to the HTTPS Worker origin and `SKILLS_ADMIN_TOKEN` in the environment:

   ```sh
   jq -Rs --arg path 'review-flow/SKILL.md' '{path: $path, content: .}' < ./review-flow/SKILL.md |
     curl --fail-with-body -X PUT "$DT_URL/api/skills/files" \
       -H "Authorization: Bearer $SKILLS_ADMIN_TOKEN" -H 'Content-Type: application/json' --data-binary @-
   ```

   Repeat with paths such as `review-flow/references/guide.md` or `review-flow/scripts/check.js`. The endpoint accepts one file per request, relative to the skills root; it does not accept `..` paths. Upload resources before `SKILL.md` to avoid a partially visible new skill. Only trusted operators may write executable skill files.
3. Check `GET /api/skills`, then `POST /api/skills/review-flow/activate`. In `/app`, choose **Reload skills** so the catalog drops its in-memory list and reads the Workspace again. The next catalog read and next Think turn see the new or edited files. The catalog and activation do not need a Durable Object reattach or a Worker redeploy. An invalid or missing description is omitted by the SDK catalog. Script edits to the type-to-flow converter still need a Worker redeploy before **Activate** or **Run type-to-flow** will execute them.

Each deployed Durable Object has its own workspace. DT uses the fixed `diagram-tool-skills` instance; update the Worker origin serving the intended environment. The current static-server deployment workflow only publishes `dist/`: a static Vite preview cannot host a Durable Object. To use this feature the Worker must serve `/app/` and `/api/skills/*` on the same origin, or the static host must proxy `/api/skills/*` to this Worker. This change does not itself deploy or change the live host.

## Local proof

```sh
npm ci
npm run generate:skills
npm run prove:converter
npm run build
npm test -- --project=unit --maxWorkers=1
npm run prove:skills  # proves Workspace primary, secondary agents:skills load on empty/unseeded Workspace, precedence, and checksum/version verification
npm run test:e2e      # includes fixture-injected browser tests for catalog, secondary load, precedence, and ambiguity confirm (no LLM)
```

Copy-paste commands to inspect the checked-in secondary package metadata and run the secondary/precedence proof directly:

```sh
node -e 'import("./skills/skills-bundle.json", { with: { type: "json" } }).then(m => console.log(JSON.stringify(m.default, null, 2)))'
npm run prove:skills
npx playwright test e2e/skill-catalog.spec.ts
```

To open the real host locally, run `npm run dev:worker` and visit the `/app/` URL printed by Wrangler. It serves the built app and the skills API together. A Vite-only development server has no skills API.

The e2e fixture injects the spike's expected skill response at the HTTP boundary; `prove:skills` separately exercises the real durable Workspace and the statically imported converter. `npm run test:e2e:preview` runs the skill fixture cases and `/app` smoke against an already-running build; set `PW_BASE_URL` to that build's origin. If port 4173 belongs to another checkout, run the full suite with `PW_PREVIEW_PORT=4183 PW_BASE_URL=http://127.0.0.1:4183 npm run test:e2e -- --workers=1`.

On a slow local host, set `PW_TIMEOUT_SCALE=3` to give the same browser assertions and test workflows more time. The default scale is 1, including CI. `PW_NO_EXTERNAL_FONTS=1` blocks optional external font hosts, and `PW_NO_VIDEO=1` reduces capture overhead.

For an `/app` change, run the live smoke against the deployed preview after deployment: `LIVE_BASE_URL=https://<preview-origin> npm run test:e2e:live`. A run against an older production deployment cannot prove the new feature.
